# 个性化操作指引助手

一个面向模拟差旅工作台的有状态AI助手：根据允许的产品知识、当前页面和用户状态给出下一步指引，支持受控导航、操作后重新观察、知识发布和回滚。运行助手不读取业务源码，付款和审批由用户在原网页执行。

**V1有限功能场景A–F已于2026-11-06通过。** Q35完成真实模型单行程持续出票和已付待票检查，Q36完成真实页面导航与未知处理，身份/事实边界及知识发布回滚复用已验证证据。M1、M2完成，M3展示材料本轮绑定真实结果；[最终验收与交付](docs/42V1最终验收与交付.md)说明各项证据、整体测试与局限。原研究后置、未验收，V1不代表全部研究目标完成。

## 实际能力与支持范围

- React/TypeScript、FastAPI、PostgreSQL组成可运行的模拟业务；个人预订、企业审批、共享券与独立票据终态保留已有实现。
- 一条真实AI持续任务完成锁价→付款→查询原付款→结束；独立检查确认有效票、唯一付款/扣款110000模拟分及库存一致，已付款尚无票时没有误报完成或重复付款。
- 从欢迎页提出目标后，真实模型调用navigate打开“预订与票据”，由实际DOM和nonce回执核对；未覆盖的国际签证问题保留未知。Q36前后业务SQL一致，没有新业务写入或worker事件。
- 管理员可审阅已有知识候选、发布、新会话使用及回滚。来源保留原构建日期；本次没有重新训练模型。

V1只覆盖自建模拟差旅v1、合成账户、选定本人单行程。A/C初态已具备虚拟付款资料和有效报价；B/D复用该任务实际取得的同一张有效票，无真实支付。模型选择动作，工程用户逐条审读后忠实点击原网页；模拟后台按显式完成事件推进，不是墙钟自主后台服务。有限样本不构成统计成功率或通用软件适配证明。

自主探索、跨版本全面适配、双行程最优规划、完整研究对照及8B/微调仍属后置研究。历史失败均保留：包括Q34等待不推进，以及Q35导航错页/缺工具被拒绝；Q36通过不改写这些失败。
