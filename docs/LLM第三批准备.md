## 实现与真实观察

App仅为原分区、控件登记固定语义ID。生产`observePage`增加可选`semantics`：选择行程布尔值、分区present/visible、控件present/visible/enabled；缺结构或某条记录表示没有采集，不能默认不存在。复数控件表示至少一个可见或可用，不保证全部可用。后端`page_observation.py`严格限制字段、页面白名单、布尔类型、重复ID及可见/存在/启用矛盾，旧观察仍保留原四字段，无额外null。

客户端呈现不能授予身份、付款资格或证明出票，当前业务事实继续使用原服务端授权投影。控件值、业务UUID、票据凭证、内部详情和完整HTML不进入观察。条件知识可在原四字段上增加`condition:{selected_trip}`及`visibility_change:{zone_id,before_source_index}`，引用同页同版本的未选→已选、分区不可见→可见实读；没有这种证据则不得生成条件关系。发布保护已覆盖页面/条件/分区证据集合，显式回滚保留；这不保证summary的自然语言语义完整，仍须审查。

使用原Edge、本机test API、同一Alice身份和第16轮有效票。没有reset、新行程、新报价、付款或worker推进。浏览器脚本调用生产观察函数，阻断全部assistant POST和业务写入，仅真实登录/GET；反例与真实学习来源分开保存。

## 原始错误离线回放

原16输入/输出文件字节保留。assistant-3使用`business_time`解释模拟业务、`observed_at`表示现实采集、`valid_until`表示观察期限；报价/锁价分别按授权valid/effective_status判断，不能把已消耗锁价称为报价过期。

| 原始来源 | 新3守卫的回放结果 |
| --- | --- |
| 第7次全文及独立`110000（币种 DEMO）`金额片段 | 拒绝amount_unverified，补旧格式遗漏；旧1/2行为保留 |
| 第7次独立“报价…expires_at 已过”原句 | 原quote.valid=true、业务时间早于期限、现实采集晚于期限，拒绝business_time_conflict |
| 第8次独立`110000 DEMO`和“此页…不能直接查进度”原句 | 分别拒绝amount_unverified与page_capability_unverified，不用首个异常代表所有错误 |
| 第12次完整修正回答 | 接受，保留1100.00模拟元、已付未出票、不重付及未知 |

正例保留未来将到期、锁价尚未过期但已消耗，以及报价有效而另一个锁价过期。守卫只覆盖有限常见句式，不是任意自然语言真实性证明。原assistant-1/2提示词、展示及回滚组合不被新3覆盖；实际active2没有启用新增3守卫。
