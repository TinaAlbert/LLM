# D3-01 的评测工程入口

本文件说明 [d3_evaluate.py](../scripts/d3_evaluate.py) 的实际范围。当前结果只查 [STATE](STATE.md)；公平信息条件与独立判据沿用 [场景 §19.4/19.5](场景与验收设计.md#194-独立验收与业务负载) 和 [D3 实施运行](D3实施运行.md)。这是同一 D3-01 的工程补充，不是新的任务或结项。

## 当前可执行范围

- `prepare-input`：用生产 `validate_guide_input`、V1知识及入口生成严格的允许输入，并冻结模型/Prompt/知识哈希、参数和统一反馈规则。B0 拒绝任何观察；B1/指引组必须提供已通过严格匿名投影契约的回放文件。工程元信息在 `host_only`，不送模型。
- `load`：本进程启动原 FastAPI/Uvicorn loopback HTTP，只连有原保护标记的 test/single-trip，串行发送同一原只读业务序列。关闭组只在工程构造入口跳过指引注册；无任务组使用原指引注册。不改生产 app、业务规则、锁、凭证、账本或现有端点。
- `verify-ticket`：通过独立只读 PG 快照核对指定合成个人行程的实际票据、当前修订、已付行程状态、锁价航段/日期与当前行程相符、非空票据证书、唯一非失败付款及其任务/票据、冻结金额与整个行程实际扣款总额、库存守恒。历史明确失败且供应商确认扣款0的付款可保留；其他历史未决/缺结果/已扣款记录使判定失败。输出判据布尔值，不接收填写 `success` 的文件，不根据模型回答/UI文字判成功。
- `baseline-round`：全部真实前置成立后，在受保护test构造固定guide/B0/B1组别，通过原登录与实际`POST /guide/next`执行单轮。复用原协调器、真实AppContainer和唯一适配器，保存允许输入、筛选候选和关联收据；无自动重试/付款/任务推进/reset。生产网页/API请求不能选择组别。
- `web-session`：全部真实前置成立后，复用上述工程构造启动有界原API宿主，同一原网页登录/委托持续多轮；只被动记录人工动作的原路由模板/状态，不读取请求体、HTTP原响应、header或UUID路径。传输包裹只计唯一适配器的实际固定HTTPS发送/读体时间，不替换模型结果。
- `snapshot`：独立只读连接保存受保护test的23表摘要/认证计数，供拒绝前后对照；不刷新模型事实或授权。
- `task-summary`：仅归并已有筛选轨迹，按group/task_ref去重；同任务plan冲突拒绝，收据关联失败/冲突保持物理次数未知，不推断模型语义、实际账单或完成率。

`prepare-input`、`load`、`verify-ticket`、`snapshot`和`task-summary`没有模型执行能力。`prepare-input`的回放不是新授权或有效期更新，不能导入真实调用；输出`not_executed`、AI分母0。单轮和持续网页入口已有执行/记录代码；当前生产完整计费及账户来源缺项，使实际CLI在PG/服务/外发前停止，真实基线仍未运行。支持代码或离线共同plan不代表原网页人工操作、连续任务或真实模型负载已完成。

## 持续网页任务与真实传输期间取证

13离线冻结的七类共同plan及B0允许输入位于忽略的`.local/d3-13/plans`，限定见`batch-preparation.json`。14的Q10改动使允许知识与入口根revision更新为2，最终UI/知识指纹见`.local/d3-14/ui-freeze.json`。七类plan规程可复用，但13旧B0输入含旧知识，不能与新UI/知识混用；实际执行前须重新prepare-input冻结各组同一版本，不覆盖旧记录。它们不是PG初态或执行成绩；未知案例具体事实、worker结局/时机及每组独立相同初态仍需在真实执行前冻结。21个候选group组合不算已启动任务分母或Q5规模，50/100仍仅物理上限。实际只做预算能容纳的任务，程序拒绝/失败/预算停止照算。

全部计费/账户/有效隔离及三件历史门槛成立后，工程显式初始化账本并准备原保护test初态；通过原网页/原API准备一个本人合成行程，真实UUID仅作本机命令参数。每组使用同一个plan、初态/事件/反馈/预算规程，独立reset受保护test；脚本不reset或推进worker。

```powershell
# 命令只是恢复入口；当前前置仍未成立。
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py web-session --group guide --trip-id '<本次test行程UUID>' --plan '.local\d3-13\plans\normal.json' --port 8000 --seconds 300 --name guide-normal-live-01
# 同一命令前台有界运行1–600秒；另用原Node启动网页，其/api代理仍指向8000。
# 只在原网页人工忠实操作；相同规程另跑B0/B1，各用新报告名。
```

保留同一Coordinator/登录/委托，原UI的续轮、取消和失效继续生效。工程侧固定group，原网页和生产API不能选择group。网络/业务不就绪不收费试探；当前`first-gate-13`真实CLI已停止在token_bound_unverified/prerequisites_unverified/ledger_not_ready，exit1、PG/宿主/模型均未启动，不计任务。

每个实际物理轮次分别保存允许输入、知识哈希、筛选候选与前后严格现存费用账本关联；B0无观察，B1与guide同实现。每个原HTTP只留路由模板/方法/状态/耗时，原UUID路径/请求响应/header不落盘；用户实际动作说明及可见必要反馈仍须按统一规程筛选保存，不让SQL结果/正确步骤进入反馈。一个session多个POST只算同一group/task_ref的一个已启动任务；不同session续做需用`task-summary`去重。

真实HTTPX传输开始/headers/读体关闭使用同一monotonic原点；没有保存供应商响应。模型进行中读取线程只在这个实际传输窗发送原`/session`、`/booking-options`、`/trips`序列，最多30请求、不发next/写业务；原认证登录/退出另列。PG仍100ms独立只读采样，短占用可能漏掉，采样与传输原点一致。传输短于30读取时保留实际样本并标不完整，不延长模型工作、补sleep或自动调用以凑数；窗口末尾已结束的GET单列，完整动作负载由原网页人工动作路由记录，不能把30读取称为全动作压力测试。

`candidate_check_ms`只包含原候选解析/两次证据过滤的同步调用；允许快照、整段adapter等待和ASGI送出分别记录。adapter等待仍含准备/结算，ASGI送出只证明交给本地HTTP层，不证明浏览器已收到。原观察3秒/整体30秒、模型20秒、IPC单次8秒及配额不延长；工程独立23表审计不插入指引工作。关闭前先停读取/采样并退出其会话，再关本轮宿主，报告线程/端口退出与错误。

对拒绝/失败例，暂停其他test/网页动作，在调用前后另用独立连接保存快照并核对23表；认证和费用另列。整个正常任务本来会改变业务状态，不能用session整体前后摘要代替每个拒绝例的无副作用对照。示例：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py snapshot --name refusal-before-01
# 在原网页完成本次受审查调用，期间无其他业务动作/worker/reset。
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py snapshot --name refusal-after-01
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py task-summary --records '.local\d3-10\guide-normal-live-01.json' '.local\d3-10\guide-normal-live-02.json' --name normal-task-summary-01
```

`task-summary`最多读取100个本目录的筛选报告，已启动任务按group/task_ref去重，前置停止/未启动不算；同名task的plan变化拒绝。收据按匿名预留引用去重，状态冲突或关联失败保持未知，未决不补零/清账，实际账单与完成率仍null。独立票据结果单列，不由归并器判断人工忠实程度或任意文字语义。旧off/idle各30成绩保留其顺序缓存/采样限制；新脚本已有计时支持变化，实际active比较前须复核同环境、请求序列、夹具及版本兼容性，必要时才重测受影响基线，不能默认直接宣称差值有效。

当前49项无费用专项只验证取证协议/拒绝/真实本地HTTP驱动和关闭，不是实际模型传输、原网页终态或active负载成绩。生产前置成立后才做实际取证；取证代码无自动下一步、业务操作或任务平台。

## 两组只读负载执行

在项目根目录、保留 PG 已启动且没有 pytest/浏览器/reset 或其他 test 使用者时串行执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py load --group off --cycles 10 --port 8011 --name load-off-01
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py load --group idle --cycles 10 --port 8011 --name load-idle-01
```

每组预检查原 test 数据库名/标记和 single-trip 夹具；端口占用直接拒绝。使用合成 Alice 登录，仅在内存持 Bearer；测量序列每轮为 `GET /session`、`GET /booking-options`、`GET /trips`，默认 10 轮共 30 请求、并发 1。登录/退出不计业务延迟分母，认证行数量另外记录。没有创建草稿或付款，因此只覆盖原业务读取路径，不能代表完整业务动作负载或真人体验。

以上名称是首次示例；已存在的报告必须保留，续做应给两组各一个全新`--name`。10月10日各次实际报告及其脚本版本只查STATE，不复写示例或将不同版本合并。

测量期间独立只读 PG 连接每约 100ms 采样连接、活跃/开启/闲置事务、锁数及等锁连接；排除采样连接自身，记录采样时刻与错误。轮询会漏掉短于采样间隔的占用；这些计数也包含同期同库连接，因此需串行和保持环境一致，不推断精确峰值或因果。

两组仅做不应调用模型的断言：实际拦截唯一适配器使用的 HTTPX async `send` 边界，尝试即计数且拒绝；同时拦截费用预留以防意外触碰账本。它们不是模型响应替身，不为任何 AI 任务给成功回答。记录本进程期间发送/预留尝试数、原三件账本文件前后指纹是否一致；不能将不存在的账本或这一个进程的零调用扩写成全机器模型活动为零。

每组保存逐请求样本、延迟 p50/p95/max、错误、PG 样本、23表前后摘要、认证变化、实际端口与服务/采样器退出。`run_valid` 只表示本次工程读取负载记录完整、保护断言成立，不是 Q5 性能通过。两组的 `fixture_state_sha256`、版本、序列、cycles、脚本哈希必须相同才能比较；先后执行顺序及缓存/系统噪声仍须披露。真实模型进行中组保持 `not_measured`，模型/过滤/交付耗时 null，不支持 `--group active`，不能用 sleep 或可控响应补足第三组。

## 公平输入与反馈规程

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py prepare-input --group B0 --goal '帮我完成这次预订，并确认是否已出票' --name b0-input-01
# B1/guide 的 observation 文件必须来自可信宿主筛选后的匿名单对象投影，不是原HTTP响应。
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py prepare-input --group B1 --goal '帮我完成这次预订，并确认是否已出票' --observation .local\d3-10\allowed-projection.json --name b1-input-01
```

示例的 `allowed-projection.json` 不由脚本伪造；没有真实允许投影就不执行第二条。不得复制模型Key、会话令牌、对象真实UUID、SQL/测试判据、工程文件或原始响应到投影/反馈。相同目标与反馈下，两组 `model_input` 只允许 observation 不同；mode、Prompt和知识哈希保持一致。人工准备投影只能检查数据形状，不能证明来源真实或时效有效，真实驱动须从宿主当轮获取并复核。

反馈规则固定为 `visible-attempt-only-v1`：只描述刚才在原控件尝试的动作与亲眼看到的必要结果，标为 user_reported，统一长度/敏感字段限制。B0不得添加隐藏事件、SQL终态或正确下一步；模型建议有误时记录拒绝/失败，不由工程驱动纠正答案。每组实际运行前仍须冻结相同初态/事件顺序、目标、合成身份和预算；按原规程独立 reset 受保护 test，工程元信息不得送模型。

## 原POST基线单轮

先在本地建立共同plan：严格字段为`task_ref`、`scenario`、`goal`、`initial_state`、`event_schedule`、`feedback_rule`、`group_order`。场景枚举normal/progress/recovery/unknown/payment_pending/paid_no_ticket/ticket_failed；组序包含guide/B0/B1各一次。事件条目仅包含`after_action`（原语义入口）和`event`（none/process_payment_job/process_ticket_task/reconcile_payment）。plan全留宿主，事件由工程侧按原规程实际推进，脚本不执行；初态说明是工程声明，真实23表前置摘要另记，必须独立确认各组相同。

```powershell
# 已启动原PG、各组初态/事件规程真实确认、计数/账户/隔离成立且工程显式初始化账本后：
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py baseline-round --group B0 --trip-id '<本次test合成行程UUID>' --plan '.local\d3-10\common-plan.json' --name b0-round-01
```

每次仅一个原POST，无自动重试。目标来自共同plan，必要反馈由`--feedback`明确标user_reported；前置失败保存`stopped_before_dispatch`、AI分母0及缺项，不创建费用三件或启动服务。原POST尝试不是完整任务，多轮按group/task_ref归并，完成率保持null直到独立终态和完整轨迹齐备。

B0真实快照仅留宿主做当前授权/最终拒绝，送模observation为null；其伪观察引用或非空amount_ref拒绝，不补金额或正确步骤。B0的payment.confirm缺冻结金额会被同一安全规则拒绝，须如实计失败；其返回来源为unverified且不会声称completion_verified。B1与guide当前模型输入和执行实现相同，应如实记录，不能人为制造改善结果。

收据在同一Slot9内、唯一适配器generate前后通过严格现存账本读取关联：包括候选拒绝后已结算usage，以及超时/取消的最大未决预留；关联失败标未知，不填0。核算上界不是实际账单，账单字段保持null直至可信账单核实。`model_wait_ms`是宿主等待整个adapter.generate的时间，包含准备/结构检查/结算，不是纯网络时间；POST差值也不能冒充纯过滤/交付耗时，这两项仍需真实负载取证。用户仍在原网页忠实人工操作；本单轮命令不能作为“模型→网页操作→独立有效票”闭环证据。

## 独立结果与留存

网页实际完成后可执行以下独立检查；真实UUID只作为本机命令参数，不进入模型或报告正文：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\d3_evaluate.py verify-ticket --trip-id '<本次test合成行程UUID>' --name ticket-check-01
```

输出 object_sha256 用于工程关联，另含独立判据布尔值，不保留凭证、证书、付款源或SQL结果行。有效票据结论只来自当前 PG 快照；即使通过，也不证明模型建议正确或原网页闭环，报告明确这两项未评估。付款未确认、已付无票、出票失败仍为终态失败，不填完成。

报告仅写`.local/d3-10/<name>.json`。12修复CLI报告名竞争：任何PG/服务/费用/模型操作前，用排他创建占用报告并flush/fsync初始`in_progress`记录，竞争者在执行前拒绝。正常返回写最终筛选报告；普通异常/键盘中断写`interrupted`与异常类，不写异常正文。硬退出保留`in_progress`；这两类记录的物理次数/实际账单/AI分母为null，不能当零费用、失败任务成绩或可自动重试证明。同名记录不得删除/覆盖以恢复；核对原命令、现存账本与可信usage/账单，再用新名称记录恢复动作。该互斥只保护报告名，不代替模型/IPC及test串行限制。

无费用负载在前置或前后快照失败时保留异常类别。基线单轮收尾快照失败仍保留已知轨迹/usage/费用，业务不变标null并判本轮无效。首次PG失败可能只有初始/中断记录；硬崩溃、磁盘故障或最终写入中断仍可能没有完整结果，不能承诺任意断电后报告完整，须结合原账本恢复关联，不补零或假造轨迹。当前没有真实模型成绩；合成筛选报告可审查后纳入交付，原始敏感请求/响应不落盘。

按变更选择下面必要检查，由主执行者串行运行；同一批实现完成后统一验证一次，通过且无新变更/失效证据就继续交付，不逐步重复运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/guide/test_evaluation_entry.py
# 前一命令结束且没有浏览器/reset时，连接原受保护test检查独立判定：
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/business/test_guide_evaluation.py
```

两组负载各自正常停止自己启动的 HTTP 和采样器。PG 的启动、收尾和受保护 test 恢复仍遵循原运行说明，由本轮主执行者统一负责；脚本不停止既有服务或重置其他空间。
