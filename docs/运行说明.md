### 失败与待确认的恢复

| 实际状态 | 下一操作与禁止行为 |
| --- | --- |
| 锁未受理且到期/修改失效 | 重新报价/锁价；修改草稿或资料在一个事务内失效依赖并释放 held |
| processing | 重启后按原 payment_id 推进持久任务；付款受理时已保护库存，不能改行程/资料/取消锁，换新 key 也不能再付 |
| unknown（`payment --outcome unknown`） | 供应商尚无确定账本，`POST /payments/{id}/reconcile {}` 仍 unknown 且不扣款；内部可按原 payment_id 继续推进成功/失败，再以新对账 key 收敛 |
| 响应丢失（`payment --outcome lost_response`） | 原供应商操作已持久扣款一次，业务 unknown；POST reconcile 读取原账本后成功并建唯一任务，不新扣款。查询没有副作用 |
| payment failed | 释放库存，旧锁和报价失效，无任务/票据；新报价、新锁和新 key 才能再次受理。对旧 payment_id 重试不会改写失败结果 |
| payment succeeded、ticket_task pending | 已付未出票，继续推进原出票任务。原锁价到期和资料随后变更不影响其冻结快照 |
| ticket_task failed | 已付、出票明确失败、无票据；保持失败终态和已售资源，不退款、不重付。本轮没有人工补偿/退款/重发接口 |
| ticket_task succeeded | 独立票据已持久化；重复处理仍同一张，不以用户声称完成作为判据 |

同 key 同参数始终返回原响应快照，即使实际状态已前进；最新状态重新 GET。同 key 异参数 409；新 key 仍受活动锁/付款唯一性限制。SQL 故障时该事务全部回滚，HTTP 503，不把部分变化当作成功。模拟供应商账本也在本地 PG；`lost_response` 用已提交账本与 unknown 状态模拟响应丢失，不声称实现跨真实供应商分布式事务。

## D2-02 生命周期、协议与证据恢复

实际是否结项、通过数、运行状态和保留数据仍只查STATE。本单元复用前节的profile、C盘固定NTFS目录、PG和观察入口；契约为场景§17.1，工程取舍为I-10。正式源码是恢复源，`.local/d2_02_*`候选/测试片段仅是过程产物，已经追加的测试不能重复追加。

启动器现在创建时把受限进程加入非继承Job，限制活动进程为1，最后宿主Job句柄关闭会结束外壳。每次启动从真实token核验专用AppContainer SID和零capability，并查询系统loopback配置确认未豁免；不把外壳ready文本当身份依据。字节管道只接受完整UTF-8行，输出每行最多65536字节、队列最多4项，输入最多32768字节，读写等待各8秒。合法结果还必须等到EOF和exit=0；额外输出、非零退出、截断、编码错误、洪泛或阻塞均失败关闭，不返回其原文。正常、拒绝和宿主异常退出均需有进程/线程回收证据。

工程probe采用schema=2，绑定当前`windows.py`与二进制SHA256，检查完整文件/网络/派生结果及UTC时间。超过24小时、未来时间、缺字段、旧schema、hash不符或探测中断都保留503。日常恢复先启动保留PG再probe；改动载荷按前节build/prepare/probe顺序重建。没有因Q6授权而自动免除probe；命令标志不扩大授权。

probe要求7类存在文件打开拒绝5，公网TCP4/6拒绝10013；回环TCP4/6有独立在线监听器宿主对照。UDP4/6回环及本机非回环UDP4接收器必须收到宿主固定数据且没有收到受限进程数据。公网UDP仅使用固定example.com DNS查询，分别向8.8.8.8和2606:4700:4700::1111的53端口探测；宿主须收到匹配响应，受限进程无响应，报告只记判据，不保留响应正文。宿主网络不通或IPv6不可用时probe失败，不跳过、不启用网络capability或loopback豁免。UDP发送成功不等于送达；公网UDP无响应未证明远端没有收到出站包，该限制单独保留。

派生探测尝试启动同一允许的shell.exe；普通宿主应可创建并以11退出，受限进程必须拒绝（本机367表示进程创建被阻止，另接受明确的5/1816）。其他创建错误、文件不存在或不可读不算派生限制证据。工程fault/reply/stall路径只在`--probe`中用于固定反例，没有任意命令执行或新增HTTP入口。

验证继续使用前节正式专项及完整pytest，结束后才运行Edge/reset；PG不可用不换SQLite。`.local/d2_02_run.py runtime|full|probe|build|browser|preserve`只是本轮命令记录辅助，写`.local/d2-02-<单元>.txt`与`-exit.json`；等价正式命令仍是pytest、manage probe、npm build/test:browser及原personal_http/corporate_http/coupon_http verify。preserve只读重验三开发空间旧终态并比较本轮前后SQL哈希，不创建订单；收尾使用原受保护reset-test后独立重读test初态及dev投影，再正常stop PG。本轮历史中断恢复应核对exit文件及实际进程，不从已失效工具session推断退出码。
