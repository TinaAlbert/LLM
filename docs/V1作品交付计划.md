## 1. 交付目标与停止扩张

近期交付一个可在本机复现的“有状态的操作指引助手 V1”：用户提出目标，真实模型依据允许的知识与当前状态选择下一步，必要时导航，用户在原网页操作，助手重新观察并正确识别业务终态。作品展示接入、工具、状态与反馈的工程能力，并诚实说明局限。

V1是独立的作品里程碑，不等于原D0–D6全部验收。用户已选择展示优先，原Q2中四类复杂能力全部通过才能首次展示的门槛不再阻塞V1；四类能力的完整研究验收仍保留为后续目标。Q5统计指标不冒充已确定，V1按下述有限功能场景验收，不宣称稳定成功率或普适效果。

| 近期必须交付 | 直接复用 | 后续研究，不阻塞V1 |

| 一条真实持续指引任务与独立有效票终态；任务状态变化后重新观察 | 个人流程、模拟支付/出票、原网页、现有观察/知识与独立SQL判据 | 双行程共享券最优规划、公平B0/B1完整矩阵 |

## 2. 已查明的阻断与实施选择

事实：Q19–Q31共13批持续任务续验未完成目标两票任务；Q23曾到第二轮，其余多在首轮被拒绝。Q31最新失败是结果词“应付额”不在有限中文语法列表；Q30另有真实导航工具缺失，不能把所有拒绝归为误拦。原记录和失败结论不改写。

依据本次授权落实的工程选择（不是用户逐字段指定的技术方案）：

- 模型继续负责理解目标、选择下一步、选择可引用的证据与必要澄清；不把完整正确路线写进程序。
- 动作、对象、参数、证据引用使用有限结构，由可信程序校验；当前金额、状态、时效、资格与终态来自允许观察。
- 用户可执行指令与关键事实采用可信呈现。中文自由说明不能成为第二个动作执行来源；未经过验证的自由说明不能因“仅供参考”就直接显示。
- 优先以已核验的资料/观察引用和当前动作生成必要解释，停止逐个补中文同义词来证明语义安全。不能简单删除说明校验后原样显示自由文本，也不能替模型补正确动作/对象/工具或把错误事实悄悄改对。
- 保留原导航工具与真实浏览器回执；缺工具仍算失败。先解决单一动作来源与稳定交付，不引入第二模型、通用语义解析器或新框架。
- 实施落点是现有action_contract.py的解析/呈现、assistant.py的正式交付、必要版本/确认/UI接线和受影响测试。既有业务规则与金额/权限不变量不迁入LLM。
- 新契约只面向新运行；历史候选与旧批保持原判定。离线新契约实验必须标为转换/合成实验，不能把改写后的旧答冒充原模型曾输出。

这属于现有单适配器内的契约收敛；2026-10-29 V1-01已实施并完成本地验证，见[41报告](41V1动作证据契约与本地交付.md)，不意味着模型效果已验证。若检查表明必须换供应商、扩大权限或重写业务架构，先报告具体依赖与影响；不得靠此计划自动扩大范围。

## 4. 固定V1功能场景

以下是有限功能验收，不是统计可靠率、Q5阈值或“6个独立模型任务”。同一完整任务可覆盖多个检查点，避免为凑数新增请求。实施前固定允许输入、初态、操作来源和独立结果；不根据结果临时更换题目。

| ID | 场景与范围 | 必需证据 |
| --- | --- | --- |
| V1-A | 本人单行程完整持续指引。复用已具备虚拟付款资料与有效报价的初态，公开声明这些前提；从提出预订目标到锁价、付款、待出票、有效票。创建草稿/绑定资料不是本次新建能力 | 每个业务选择来自真实模型正式建议；用户忠实点击；模拟worker按预先固定机制推进；最后一次状态核对和独立有效票/唯一付款/金额一致；不能由工程补步凑成功 |
| V1-B | 从不同页面求助，能基于当前页面导航到已存在入口并继续会话 | 至少一次真实模型工具提案、浏览器执行与回执；不能用合成ACK或静态链接替代 |
| V1-C | 已付款尚未出票，以及一个已选定的状态变化/恢复检查点 | 不把付款等同完成、不建议重复付款；用户操作/状态变化后重新观察，旧结果失效。可以作为V1-A的检查点 |
| V1-D | 未覆盖问题或缺少必要事实 | 真实助手正确说明未知/澄清；不泄漏隐藏信息，不以程序永远拒绝代替正常任务 |
| V1-E | 切换账号/对象、伪角色、迟到结果及一次关键事实篡改 | 复用相关有效反例，只对受影响部分复验；错误数据不交付，业务无越权副作用。无需为这些程序边界额外调用模型 |
| V1-F | 已审核知识候选→发布→新会话使用→回滚 | 原管理界面与版本/来源记录，必要回读；使用既有真实构建候选时注明来源和日期，不声称本次新训练，不把回滚当跨产品版本适配 |

支持范围必须出现在作品说明里：自建模拟差旅、当前已验证版本、单行程选定初态、合成账户、无真实支付。完整原F/A矩阵中尚缺的能力明确留在研究待办，不能宣称原项目全部完成。

## 5. 验证与工期收敛规则

1. 每个阶段一批相关改动完成后，集中运行一次受影响检查；新改动/失败/失效才做定向复验。文档调整不触发业务回归。
2. 权限、金额/状态真实性、独立终态、费用账本和必要隔离不能省；局部语法同义词、无关业务全套、重复prepare/rehearse不再逐轮串行消耗。
3. M1将真实失败分成结构/工具、证据/事实、展示兼容三类，修一类问题而不是每个词新开一个编号。保留一份有来源的失败样本清单与固定预期。
4. 对同一契约问题最多安排两轮集中实现/验证。仍阻断时，在同一任务内写明未解决点、是否有更小实现、对V1的影响；停止追加词表与新版本号，不擅自降低验收或默认发起第三轮收费试错。
5. 验证通过即进入下一交付包；额外美化、重构、模型对比放后续。进度报告固定回答“哪些V1场景已取得证据、哪个阻断尚在、下一步怎样解除”，不以测试数量替代业务进展。
6. 不把“工程收尾”称为“真实任务成功”；V1完成后也不写原D4/D5/D6全部通过。研究阶段何时启动由用户再排期，不能自动续接。
